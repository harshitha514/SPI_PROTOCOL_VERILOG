# SPI_PROTOCOL_VERILOG
Verilog HDL implementation of the SPI (Serial Peripheral Interface) protocol featuring Master-Slave communication, full-duplex 8-bit data transmission, clock generation, shift registers, and serial data synchronization. Designed and verified using QuestaSim through testbench simulation and waveform analysis.

SPI Protocol – Verilog HDL Implementation

📌 Project Overview

This project implements the Serial Peripheral Interface (SPI) Protocol using Verilog HDL. It consists of an SPI Master and an SPI Slave module that communicate with each other through synchronous serial data transmission.

The design demonstrates serial-to-parallel and parallel-to-serial data conversion using shift registers, clock generation, bit counting, and control logic.

🎯 Objectives

Understand the working principle of the SPI communication protocol.

Design SPI Master and Slave modules using Verilog HDL.

Implement serial data transmission and reception.

Understand clock synchronization and data sampling.

Verify communication between Master and Slave using a Verilog testbench.

⚙️ SPI Protocol Overview

SPI is a synchronous, full-duplex serial communication protocol commonly used for communication between microcontrollers and peripheral devices.

It uses four communication signals:

Signal

Description

SCLK

Serial Clock generated by Master

MOSI

Master Out Slave In

MISO

Master In Slave Out

CS

Chip Select (active low)

🏗️ Project Architecture

The design consists of two main modules:

1. SPI Master

Generates the SPI clock using a clock divider.

Controls Slave selection using Chip Select.

Transmits parallel data serially through MOSI.

Receives serial data through MISO.

Uses shift registers and a bit counter to manage data transmission.

2. SPI Slave

Responds to the Master when Chip Select is active.

Receives serial data through MOSI.

Transmits serial data through MISO.

Uses shift registers to convert serial data into parallel data and vice versa.

Maintains synchronization with the Master-generated SPI clock.

🔄 Working Principle

The Master initiates communication by pulling Chip Select low.

The Master generates the SPI clock.

The Master transmits data serially through MOSI.

The Slave receives the incoming data.

The Slave transmits data simultaneously through MISO.

The Master receives the data from the Slave.

After completing the required number of bits, the Master deactivates Chip Select.

Data Transmission: MSB first.

Clocking: The Slave prepares the next transmission bit on the falling edge, while the Master samples the received bit on the rising edge.

🧪 Verification and Testing

The SPI Master and Slave modules are verified through simulation using a Verilog testbench.

The testbench checks:

Reset operation.

Master-to-Slave data transmission.

Slave-to-Master data transmission.

Full-duplex communication.

Serial data ordering (MSB first).

Chip Select operation.

Correct received data.

Completion of data transmission.

📊 Expected Results

The simulation waveform is analyzed to verify:

SPI clock generation.

MOSI and MISO data transitions.

Chip Select activation and deactivation.

Correct serial-to-parallel conversion.

Successful data exchange between Master and Slave.
